Lógica de Procesamiento y Automatización de Reglas de Negocio

1. El Algoritmo como Motor de Decisión

Un algoritmo es una secuencia finita de instrucciones precisas. En la informática aplicada a los negocios, los algoritmos son la traducción técnica de las **Reglas de Negocio Contable**. Sin una lógica algorítmica sólida, el sistema es incapaz de garantizar la inmutabilidad y la veracidad de la información.

El estudiante de Ingeniería Aplicada debe desarrollar el "Pensamiento Computacional": la habilidad de descomponer procesos contables manuales en pasos lógicos ejecutables por una máquina.

📜 Texto de Cátedra (Programa p.4)

"El dominio de las nociones lógicas primarias es el requisito esencial para comprender cómo un programa ejecuta tareas de fiscalización. La diferencia entre un dato y una instrucción radica en que el dato es el objeto de la transformación, mientras que la instrucción es el algoritmo impuesto por el perito profesional para cumplir con los principios contables generalmente aceptados."

2. Estructuras Lógicas Fundamentales

2.1 Estructuras Condicionales (Toma de Decisión)

Son el corazón del control interno. Permiten que el sistema decida basándose en el estado de una cuenta. Por ejemplo, decidir si se emite una factura con retención o no.

Lógica de Aplicación de IVA (SI / ENTONCES):

  • Si (Monto > 0) Entonces IVA = Monto / 11.
  • Sino IVA = 0.
  • Fin Si.

2.2 Estructuras Iterativas (Bucles de Procesamiento)

Permiten aplicar una regla a miles de registros simultáneamente. Es lo que permite procesar una planilla de sueldos para 5,000 empleados en segundos.

3. Gestión de Datos y Variables

Para construir un sistema, debemos definir cómo "nombrar" las cosas en la memoria de la computadora.

3.1 Tipos de Datos Contables

  • Integer (Entero): Para números de cuenta e IDs de transacción.
  • Decimal / Double: Para montos en moneda (PYG). **Vital:** Manejo de precisión para evitar errores de centavos.
  • Boolean: Para estados de verdad (Pagado = TRUE / FALSE).
  • String (Cadena): Para nombres de proveedores y descripciones.

3.2 Constantes vs Variables

Una **Constante** es un valor que no cambia durante la ejecución (ej: el porcentaje de IVA 10%). Una **Variable** es un valor que muta (ej: el saldo actual de Caja que cambia tras cada asiento).

📌 IMPORTANTE: Un error en la definición del tipo de dato (ej: usar enteros para montos decimales) causará fallos en los balances consolidados.

5. Laboratorio Práctico: Automatización del Balance de Sumas

Utilice la siguiente lógica para validar la integridad de un balance de prueba de 5 registros.

// Algoritmo de Auditoría de Balance
VAR Suma_Debe, Suma_Haber, Diferencia
PARA cada Asiento EN Diario HACER
    Suma_Debe = Suma_Debe + Monto_Debe
    Suma_Haber = Suma_Haber + Monto_Haber
FIN PARA
Diferencia = Suma_Debe - Suma_Haber
SI (Diferencia == 0) MOSTRAR "Balance Cuadrado ✅"
SINO MOSTRAR "Error de Partida Doble: " + Diferencia

6. Guía SOS: Solución de Errores Lógicos

🆘 "QUÉ HACER SI..."

- EL RESULTADO DA DECIMALES EN GUARANÍES: PYG no usa céntimos. Implementa la función TRUNCAR() o REDONDEAR(monto, 0) en tu algoritmo inicial.

- EL BUCLE SE QUEDA PEGADO (INFINITO): Te falta una condición de salida. Verifica que el contador del bucle esté aumentando en cada iteración.

- EL SISTEMA NO RECONOCE EL TIPO DE CUENTA: Es un error de la fase de Colección. El ID de cuenta en tu algoritmo debe coincidir exactamente con el ID del Maestro de Cuentas.
